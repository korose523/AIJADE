## Gap and frozen boundary

The offline manifest scorer is qualified, but the live driver still branches on
H/I1–I8/S1. A run on genuinely new cases must not obtain its intervention or
expected result by recognizing such names. Add a separate, manifest-driven live
driver without altering the measured adapter, mapper, authority, common promotion
gates, existing C1/C2 policy or any historical driver/data/scorer. The previous
331-file source freeze and old complete packet verifiers must still pass.

Construct the live input only from the ten already-known declared scenarios,
prior balanced order and source-to-alias map. Use explicit input operations:
run/omit execution, optional mapper act override, selected receipt case, optional
declared asset override, claimed stage, repeat outcome actions, revoke before
reuse and injected authority-write fault. These are interventions, not expected
outputs. Catalogue selection uses the actual task/code fingerprint; the
self-verdict is read from the matched archived candidate trial. Keep program,
benchmark, model/asset/clip, source identities and stage unchanged.

The live runtime manifest contains no case class, scoring window, expected
promotion, expected C1/C2 answer or engineering pass flag. All decision-facing
data still travel through actual memory, sandbox, mapping, receipt/admission and
the unchanged adapter. Case IDs only bind records. The parser rejects unknown
fields, missing/wrong types, duplicate identities, dangling receipt references,
invalid programme/act/condition values and an enabled held-out purpose. It must
accept consistent renaming and bounded counts other than ten. The interface may
hold at most ten pairs/twenty databases in one renderer block.

Commit/push the constructed known runtime fixture and its exact derivation before
the C# live implementation. It is input construction for known development
scenarios, not a new held-out set or blinded design.
