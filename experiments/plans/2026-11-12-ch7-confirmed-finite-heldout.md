## Construction rules, before seed or cases

Four blocks contain one case from each original family: normal, eight integrity
families and semantic-limit. Block b (zero based) uses programme b from the usable
pool except execution-failed, which uses programme b from the unusable pool.
The requested act cycles over `[inform, comfort, celebrate]` by (b + family index)
modulo three. Semantic cases override to the next act, making a known allowed-act
mismatch; the requested act never repairs the stored act. The foreign-receipt case
uses the normal, semantic, execution-failed and revocation case respectively in
blocks 0–3; it never uses its own receipt. Asset mismatch flips one hex digit of
the actual model hash at positions 0, 15, 31 and 63 respectively. A valid but
different declared version is recorded; asset/model/clip bytes are held fixed.

Duplicate commits are replayed respectively before delivery, after delivery,
after the first reuse and after the duplicate reuse. There is exactly one initial
and one replayed commit, plus one initial and one duplicate reuse. Record each
operation boundary and intermediate actual snapshot. Revocations occur
respectively before delivery, after delivery, after an actual outcome-memory
probe and after an actual authority-state probe; all precede the guarded reuse.
The latter probes are observation-only and never override the authority read by
the unchanged adapter. Transactional faults are injected respectively before
authority insert, after authority insert, before outcome insert and before outbox
insert. SQL exception details must witness real promotion/report visibility and
the concrete table/operation/counts inside the failing transaction; P0002 or any
other unexpected error stops the sequence. No expected C1/C2 outcome is asserted
inside the measured driver. Unknown execution is actually omitted, and failed
execution uses its selected originally failing programme without changing tests.

After the implementation is frozen, derive the generation seed as SHA-256 of
`aijade-ch7-confirmed-40-v1:` plus the full freeze commit. Opaque case IDs are
SHA-256(seed + block + family) prefixes. Sort family order inside each block by
its seed-derived hash; in the first five ordered pairs C1 runs first, in the
remaining five C2 runs first. Both arms share the same actual registered intent,
sealed receipt inputs, programme, operation placements and original database
continuity. Preserve the family map separately from the runtime; this is not
blinding. Record the deterministic seed and complete allocation once generated.

Suitability checks, completed before measurement, must verify the exact 40/80
population, one family per block, 5/5 first-arm balance, four different programmes
per family, declared operation consistency, all frozen source/candidate hashes,
all 28/32 opportunities, and novelty against old cases after ignoring identifiers
but retaining programme, act, evidence relationships and operation placements.
These are AI-assisted generator/schema checks, not independent human semantics.
Do not call four variants four independent fault families.
