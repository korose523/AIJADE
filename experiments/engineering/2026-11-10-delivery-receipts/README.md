# QQ 交付观察与网页可见状态

起点为 `d10341bb581e95b46ffcb3fd6e30e94b65ddee11`。本轮继续共享运行时架构，把已存助手回复关联到普通 QQ 回复及共享运行时命令的发送尝试；沿用 PostgreSQL `config_kv` 与账号／角色／QQ 绑定授权，没有新增服务、项目、NuGet 包或数据库迁移。原始命令、计数、跳过项、源码／二进制指纹及文件校验和见 [receipt.json](receipt.json)。

记录包含来源消息身份与全文哈希、目标、开始／结束时间，以及各个文本／图片／语音请求的指纹、平台消息编号和结果。普通角色读取不携带整个交付日志。连接器在发出请求前登记片段，只有完整成功回执才允许下一片段；拒绝、未知或观察无法持久保存时停止，不自动重发。网页读取同一角色的记录，并区分准备／发送中、平台回执、拒绝、未知与中断。

本轮实际检查：

- 来源所有权、角色隔离、绑定目标、撤销授权以及并发重复登记。
- 缺返回码、缺消息编号、异步响应、矛盾字段、错误类型、无效 JSON、过大响应、HTTP 500、丢失连接和调用方取消。
- 文本片段已确认而图片片段被拒绝时，原回执保留，后续语音不再发送。
- 来源登记失败时零平台请求；已获平台响应却无法保存观察时，停止剩余片段并记为未知。
- 进行中记录不能为新增记录让位；超期投影未知，较早已结束记录按上限滚动清理；原聊天保留。
- 实际签名 OneBot HTTP 入站、生产 bridge、应用 API、PostgreSQL 与 Chromium 中的拒绝／未知／接受状态，网页重载后仍可读取。

每角色最多 128 次尝试，每次最多 64 个片段；未结束记录超过 10 分钟投影为未知，清理请求限 3 秒。去重只覆盖仍保留的尝试身份，不是永久 exactly-once、重复入站事件去重或持久补发 outbox。自动主动消息、提醒、绑定及连接器内收藏导入仍走原路径，不在这份来源关联日志中。

这些是授权 relay 上报的观察。回执不证明用户收到或已读，服务端也不能独立阻止 relay 伪造上报；它们不替代论文所需的外部执行证据。平台、模型与媒体响应均为合成夹具，没有接通真实 QQ 账号或新增模型运行。之前本地模型的成功及失败继续按原目录保留，不移作本轮结果。

`research-protected.json` 保存起点的 622 个研究、共同基础和声明测量文件的指纹；全部逐字节不变。论文 9,878 项事实由原 Python 3.9.6 构建解释器重新取得，与修改前完全一致。本轮只补充系统方法、工程证据与相应边界，不填写第 7 章保留集结果，不运行 P2 主再生成或新 P3-E 科学评估。

开发阶段一次编译命中 xUnit2031（`Assert.Single` 的筛选写法），修正前日志保留。最终构建和全量／浏览器检查分别留有原始记录。协议来源已按固定提交核对，记录于 `protocol-source-check.json`；未导入第三方实现代码或素材。
