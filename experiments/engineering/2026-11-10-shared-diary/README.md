# 共同日记、时钟修复与本地模型开发检查

本轮在 `4af8d5b9756dbc95f7a70b8afa89ff0192169918` 上继续陪伴架构，沿用共享运行时代码库、HTTP 授权和 PostgreSQL；未新增 .NET 项目、NuGet 包、数据库表或常驻服务。逐项结果、命令、跳过清单、源码与产物 SHA-256 见 [receipt.json](receipt.json)。本目录是产品工程记录，不是论文主实验数据。

- **共同日记**：网页与绑定 QQ 通过 `/diary save` 保存一段普通对话，通过 `/diary` 或日期读取；网页可遗忘摘录。服务器读取真实存储消息，校验所属账号、角色、同一聊天和顺序；保存来源 ID、时间戳、首次保存时采用的时区、全文哈希和有界摘录。并发重复保存幂等，删除采用修订号。摘录为显式共享的数据；原聊天和私人记忆库仍分开。日记不自动生成，也不是不可改写的研究证据或历史版本档案。
- **时钟注入**：上一提交的 GitHub Linux CI 失败不是通过更改预期值解决，而是修正默认时钟覆盖显式注入的问题。新增韩国、UTC、洛杉矶三种注入时区用例；最终全量本地回归使用 UTC。
- **可见回复**：产品工厂补充普通可见文字指令，保留旧直接构造入口的默认提示。仅有情绪标记时仍拒绝完成回复，不自动重试，也不编造兜底答案。实际 1.5B 检查没有因新增指令而通过。

| 实际模型尝试 | 结果与适用范围 |
|---|---|
| `live-qwen15/` | 缓存 Qwen 1.5B 的首轮请求仅输出情绪标记；检查失败。首版夹具未结构化记录失败码，保留原始响应、测试失败与运行资源轨迹 |
| `live-qwen15-visible/` | 补充可见文字指令后仍仅输出情绪标记，明确记录 `EMPTY_REPLY`；检查失败 |
| `live-llama8b/` | 通过 60 秒 RAM 准入后，8B 冷加载超过普通 300 秒请求期限，记录 `UPSTREAM_TIMEOUT`；没有触发资源强停 |
| `live-llama8b-ready/` | 在同一 600 秒资源守卫内单独预加载约 246 秒，再完成两轮合成英文聊天；日记保存、读取和遗忘通过，额外聊天模型请求为 0，原聊天保留，退出时卸载模型 |

8B 就绪后的两个上游请求约为 33、26 秒。这是记录器收完真实响应的耗时，不是首字或流式延迟。上下文为 4,096 token，输出上限为 256 token，不能与正式研究的输出预算混同。模型身份、Ollama 版本、实际请求／响应、加载状态、资源采样、预加载条件和原始 TRX 均在各尝试目录中。没有下载、复制或修改权重。8B 准入前仅退出本轮闲置的 .NET 构建服务器，未关闭用户应用或清空系统缓存。两个早期 1.5B 尝试的执行前指纹不完整，不能以后补指纹替代；两次 8B 尝试另有执行前源码和二进制指纹。

浏览器套件使用实际 AIJADE 服务、PostgreSQL、Chromium 和签名 OneBot HTTP 入站，模型、图片、歌声和 QQ 出站为受控夹具；真实模型另按上表记录。第一轮新日记浏览器用例因等待错误的绑定回执文字失败，第一轮定向集成用例因 QQ 夹具身份格式不合法失败；修正与重跑均保留。两次开发编译的分析器错误也保留在 `build-*.log` 中。

`research-protected.json` 列出起点的 552 个研究、共同基础和声明测量文件的 SHA-256，本轮逐字节不变。论文沿用原 Python 3.9.6 构建解释器，9,878 项事实与修改前完全相同；跨解释器末位差异及稿件精度检查见 `paper-facts-comparison.json`。产品提示已经变化，冻结记忆文件未变不等于新旧提示等价。

真实 QQ/NapCat 平台送达、授权语音与歌声、长期陪伴质量、持续运行容量与正式模型资格仍需各自验收。本轮没有运行 P2-R-Mac 主再生成、新的 P3-E 科学评估或第 7 章保留集 C1–C2 比较，也没有训练、发送邮件或向导师提交材料。构建与工程通过不提升这些研究状态。
