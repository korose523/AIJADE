# Measured chronology and the remaining causal-prefix qualification

Scope audit: 12 November 2026 (Asia/Seoul), after both development attempts and
their independent record reconstruction. This is an observed boundary, not a
prospective amendment or supervisor approval. All original records and numbers
remain unchanged.

The controller and source establish this actual order:

1. `Prepare_archived_executions_and_register_before_render_dispatch` executes the
   selected archived code, maps the allowed acts, registers and sends the intents.
2. Godot ends its shared session and closes the receipt file.
3. `Qualify_ten_declared_cases_on_the_staged_C2_path` creates each fresh case
   database, writes and retrieves its initial cue, imports the already prepared
   receipt events, admits the proposal, processes promotion/state/outbox, delivers
   the outcome through product perception and retrieves it for round-2 reuse.

The initial retrieval in step 3 is a real interface check, but it does not cause
the earlier execution or render mapping. The second-round read/state/reuse path
is actually executed in the case database. Fixed logical timestamps in the
event envelopes must not be read as wall-clock proof of the opposite order;
controller phases and the call order are the relevant evidence.

The ten declared cases therefore qualify the **artifact-replay path from receipt
import/admission through promotion, authoritative state, outcome delivery and
second-round reuse**, with their finite identity/state invariants. They do not
qualify a retrieval-led causal first round, a live online loop or a C1/C2 effect.
The original PASS_DEVELOPMENT_QUALIFICATION_ONLY flags have this narrower scope.
S1 remains an admitted/reused semantic counterexample; no failed case is hidden.

Before writing or executing a new held-out comparison, implement and prospectively
freeze a same-round retrieval-led execution/render prefix on the same owned case
state, qualify that ordering, and then freeze the C1 baseline, both conditions'
checks, mapper/state policies and scoring. The intended architecture graph in the
parent README describes that later causal order; its initial retrieval-to-
execution edge was not exercised by the archived development batch. Case counts,
order and formal protocol approval remain open. All existing development cases
remain development material.
