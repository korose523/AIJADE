# Lossless transport scaffolding; no E5 archive or semantic acceptance

This directory implements a generic byte-transport envelope and its controls. It does not create an E5 packet, invent an E5 outcome, change the immutable E4 packet or replace any caller's semantic verifier. No Git, native/process census, API or model operation is invoked.

`lossless_members.encode_file(source, directory, logical_name)` streams the original file without parsing or rewriting its contents. It produces one new exclusive envelope directory, with a logical original SHA/byte count and a contiguous ordered member list. Default decoded members are **16 MiB**, and every physical object has its own **32 MiB** encoded ceiling. The codec's larger configurable safety ceiling is deliberately conservative; it is a local transport policy rather than a statement of an external provider's current official limit. Even incompressible large logical input is divided into bounded physical objects.

Each physical object is exactly one gzip member, with level 6, empty filename, flags zero, mtime zero and the fixed header. SHA/size identities bind both encoded and original decoded bytes. Original source ownership/type/link identity is checked on the same file descriptor and again through the path before sealing. A changed/truncated source or oversized object leaves an unsealed partial directory; it does not silently truncate or normalize input. Empty logical input has one complete empty member.

`verify_envelope(directory, expected_envelope_sha256=..., logical_cap_bytes=..., output=None)` requires a separately fixed envelope SHA. It rejects duplicate metadata keys, noninteger/boolean size substitution, wrong member count/order/offset/name, missing or extra files/directories/symlinks, unsafe logical names and all size/hash mismatches. Each member is decoded using a single `zlib.decompressobj` with explicit EOF validation. Concatenated members, even an extra empty member, any trailing bytes, corrupt CRC/trailer, optional header fields, truncation and decoded-bound overflow all fail closed. Both encoded reads and decoded output steps are bounded at one MiB. Logical output is a hash-verified concatenation, with no JSON rewrite.

Optional output is written only to a new project-local partial file. Successful full verification promotes it atomically with a no-overwrite hard link; failures retain the partial and never expose it under the requested final name. Existing output is not overwritten. Read-only member verification can also check a legacy single-member source independently of the generic envelope; this is transport verification only.

The actual controls in `codec-controls-01/` pass **27/27**, including tiny opaque bytes with whitespace/CRLF/duplicate-key spelling/non-UTF8 data, empty input, deterministic large streaming, corrupt/truncated/concatenated/trailing-member faults, both SHA levels, exact population and type/size caps, rejected-output handling and existing-output protection. The synthetic large source is **134,217,728 bytes (128 MiB)**; two independent encodes produce byte-identical envelopes and all eight gzip members. All original decoded bytes are verified by whole-file SHA/size without writing a second 128 MiB raw copy. Its encoded total is 588,992 bytes in this highly compressible synthetic fixture; that ratio is not a claim about future E5 telemetry or worst-case compression.

The existing immutable E4 telemetry gzip is also read without mutation: 8,127,250 encoded bytes decode exactly to the original 66,926,629 bytes and SHA `92c355dd…`. No old cold guard, process observation or engineering/scientific acceptance is repeated or supplied by that check. Determinism is demonstrated under the recorded zlib compile/runtime version 1.2.12; the raw logical identities remain authoritative across any future codec/version change.

Future integration is intentionally not implemented here. After the actual E5 terminal audit exists, root/audit agent must select the exact complete original population, bind each original logical SHA/size and source map to a fixed envelope SHA, preserve all member physical identities in the actual packet manifest, and adapt its byte reader without changing the meaning, denominator or phase/terminal predicates. A verified private decoded file or streaming reader can then feed the unchanged result-specific cold semantics. E4's existing mappings and manifest are immutable. Generic transport success is never a backend, hardware, human, author, seed or held-out result.
