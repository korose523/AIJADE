## 2. 为什么标准化泄漏必然为 0（这不是巧合）

全局 standardize 对**每一列**施加同一个仿射变换 $x \mapsto (x-\mu)/\sigma$，且该变换
**在切分之前一次性施加于全部样本**。于是：

1. 变换是**单调**的（$\sigma > 0$）；
2. pooled AUC 是**秩统计量**（只依赖样本间的相对顺序）；
3. 训练折与测试折被施加了**同一个**变换。

⇒ 秩保持不变 ⇒ pooled AUC 逐位相同。**因此 `(1)` 与 `(2)` 的差在数学上就该是 0，实测 0.000 是对实现的验证，而不是一个发现。**

> 📌 附带的方法学要点：标准化泄漏**只在**下列条件下才真实存在 ——
> (a) 指标不是秩不变的（例如校准误差、log-loss、绝对阈值下的 F1）；
> (b) 标准化在**每一折内独立**进行，使折间特征尺度不一致；
> (c) 变换依赖标签。
> 本条对后续设计有意义：若要报**校准**指标，standardize 必须移入折内。

## 3. 特征选择的（近）无影响也有结构性原因

各折选中的子集**高度稳定** —— 10 折中 **12 个特征始终入选**，只有 `entity` 在 fold 8 额外入选（k=13）：

```
始终入选(∩) : length, secondPerson, temporal, meanIdf, selfDisclosure,
              isQuestion, noveltyIdf, isBackchannel, contentDensity,
              commitment, possessive, pastVerb        （12 个）
至少一次入选(∪): 上述 12 个 + entity
```

当"用标签选特征"几乎总是选出**同一个**子集时，该步骤本身就不携带可泄漏的信息量。
这也解释了 `(2)→(3)` 之差为何趋近于 0。

**但必须同时记录一个更值得注意的现象**：

| 估计 | AUC |
|---|---|
| `PRIOR`（**零标签**先验权重） | **0.796** |
| `LOCV` / `Nested`（学习到权重） | 0.812 / 0.815 |

⇒ **判别力主要来自特征本身，而非学到的权重**。学习权重相对零标签先验只带来 **+0.016 ~ +0.019** AUC。

> ⚠️ 注意 `PRIOR` 的权重是**用标签调过**的（registry 注记为"已知被特征选择+权重污染"），
> 所以 0.796 本身不是干净下界。真正干净的下界需要一组**未经标签触碰**的权重才能给出。
> **这是一个尚未闭合的点**，已列入 §5 待办。

## 4. 这个阴性结果为什么比阳性结果更有价值

审计的原始动机是"自证清白"：先假设自己的数字有泄漏，量化它，给出更保守的估计。结果是没有泄漏。
这看似白做，实际有三重价值：

1. **它把"我们的 AUC 可信"从断言变成了证据。** 论文里写"我们做了嵌套 CV，未发现乐观偏倚，
   估计值 0.815"远比只报 0.812 有力。
2. **它给出了一条可迁移的判据**（§2）：标准化泄漏对秩不变指标在数学上为 0。
   后续研究者可据此**省掉**这一步无效工作，或识别出真正需要折内标准化的场景（报校准时）。
3. **它把注意力推到真正的弱点上** —— 0.796 的零标签先验说明**特征工程才是瓶颈**，
   不是拟合方法。这与 P1.5 / H5 的结论（瓶颈在检索器而非遗忘策略）方向一致：
   **本项目当前的瓶颈在"表示"，不在"学习"。**
