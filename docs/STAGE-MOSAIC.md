## 一、现状

| | AIJADE | MOSAIC |
|---|---|---|
| **舞台** | Web 与桌面应用里的 MMD 舞台（`tools/mmd-bundle`）；另可经渲染器契约驱动 MOSAIC 的 Godot 客户端（Bots 宿主的 `Renderer:MosaicPort`） | 工作台启动的 Godot 原生客户端；她的家 20 m × 16 m（卧室、客厅、厨房和餐厅、院子），家具 39 件 |
| **身体能做什么** | 表情、视线、头部姿态与倾听点头；不走动（渲染器契约的 `locomotion_mode` 只渲染 `idle`） | 走到家里 10 个地点（绕开家具），坐下、躺下、站起；"过来""走开"等按目标走；手势、舞蹈；动作智能体已接入，但动作库还是空的 |
| **谁决定动作** | 回复的 PEF 意图决定表情与姿态 | 用户的话按固定词表决定（含否定词，以及"我去睡觉了"这类说话人自己要去的情况）；用户没要求时，模型可从一张封闭的动作表里选，或不动；空闲时由小脑决定动不动 |
| **知道自己在哪** | 不知道（舞台上没有地点） | 每轮把"她在哪"（`where_you_are`，例如"在客厅，沙发，坐着"）交给语言模型；没有这一句时，模型会编一个地点 |
| **回复前告诉模型要动** | 无 | 有：`app_action` 说明回复之后应用会让她做什么；为 null 时不要答应动 |
| **说话** | 服务端语音合成，网页舞台口型同步 | 工作台合成语音，Godot 客户端口型同步 |
| **接口** | 渲染器契约：本机 UDP，每个数据报一个 JSON 包 | 工作台 HTTP（默认 `http://localhost:5002`，无认证）：`POST /api/v1/live-scene/command` 收一行文字指令，`GET /api/v1/live-scene` 返回进程状态与原样的 `live-status.json` |
| **研究边界** | 渲染器发送端 `src/Aijade.Integrations/Renderer` 是第 4 章外部比较的研究对象 | 工作台与家属于非研究线（`research_gate_effect: none`） |

## 二、约束

- **渲染器契约不能用来走路。**
  - 契约只有表情与头部姿态，`locomotion_mode` 只渲染 `idle`；走路、坐下、躺下都不在其中。
  - 发送端是第 4 章的研究对象，只能调用，不能修改。所以 [COMPANION-CONTRACT](COMPANION-CONTRACT.md) 原来"经现有渲染器契约驱动"的设想，只能做到表情和头部。
- **工作台的指令接口。**
  - 一行指令按 `;`、`；` 或换行分隔，任一条出错，整批都不发送。
  - 相关指令有 `表情 v a d c`（效价 −1…1，其余三项 0–1，与 AIJADE 的 PEF 情绪向量同义）、`说 文本`（1–300 字）、`去 地点`、`起来`、`走路 过来`、`手势 鞠躬`、`跳舞 名字`。
  - "她在哪"只在工作台内部算出，交给它自己的语言模型；接口不返回这一句。
- **浏览器不能直接调用工作台。**
  - AIJADE 的 Web 端是 Blazor WebAssembly，运行在浏览器里，调用另一端口的工作台会被跨源规则挡住。
  - 桌面应用（MAUI）与服务端是本机 .NET 进程，不受这个限制。
- **一次只能有一个大脑。** 工作台自己会先开口（`ProactiveSpeech`），也会自己选动作（`ModelActions`）。AIJADE 驱动她时这两项要关掉，否则两边都会说话、都会让她动。
- **动作由用户的话决定，不由模型决定。** MOSAIC 的理由是小模型会编造做不到的动作，所以用固定词表；回复前用 `app_action` 告诉模型将要做的动作，免得模型说做不到，或答应应用不会做的动作。
- **坐着、躺着时。** MOSAIC 在她坐着、躺着时不做空闲动作，躺着时不主动开口。

## 三、可选方案

| 方案 | 做什么 | 改动与风险 | 评价 |
|---|---|---|---|
| **A. 经工作台的文字指令（建议）** | AIJADE 用自己的人设与记忆回复；按共享词表判定这句要不要动，回复前告诉模型；回复后给工作台发一行指令：表情、说话、去某处或做动作 | AIJADE 侧只改非研究线，并在契约里加"舞台"一节；MOSAIC 侧需要在状态接口返回"她在哪"（交接）；两边的词表要靠向量保持一致 | 唯一能让 AIJADE 的对话带上整个身体的做法 |
| **B. 只用现有渲染器契约** | 维持现状：表情与头部姿态 | 无改动 | 不能走路、坐下，也不知道在哪 |

| **D. 把用户的话转给 MOSAIC 自己聊** | AIJADE 的界面发 `聊天 用户的话`，MOSAIC 用自己的模型和记忆回复 | 改动小 | AIJADE 只剩一个输入框，没有融合 |
| **E. AIJADE 作 MOSAIC 的对话大脑** | MOSAIC 把 `CompanionUrl` 指向 AIJADE 提供的、与 Ollama 兼容的接口（见 COMPANION-CONTRACT"以后可以考虑的"） | 两套记忆并存；MOSAIC 送来的消息已含它自己的记忆与动作说明，AIJADE 要原样透传 | 等两套记忆的问题有了答案再考虑 |

## 四、方案 A 怎么做

### 1. 一轮的顺序

1. 用户在 AIJADE 的聊天里说话。
2. AIJADE 用共享词表判定要不要动：
   - 判定对象：去某处、过来或走开、起来、跳舞、手势；
   - 有否定词时不动，说话人自己要去（"我去睡觉了"）时也不动。
3. 在用户的话之前加说明，用的是文字渠道已有的 `SendAsync` 重载：
   - 要动时，说回复之后应用会让她做什么，用几个字答应，不要说做不到；
   - 不动时，说这一轮应用不会让她动，不要答应动；
   - 知道她在哪时，再加一句位置说明。
4. AIJADE 照常生成回复。
5. 给工作台发一行指令，例如 `表情 0.70 0.60 0.50 0.50; 说 好呀，我去沙发上坐会儿。; 去 沙发`：
   - 表情取回复的 PEF 情绪向量；
   - 回复里的 `;`、`；` 和换行换成逗号；超过 300 字时分成几条 `说`。
6. 此时 AIJADE 自己的语音和网页舞台不出声，免得出现两个声音。
7. AIJADE 的先开口（契约 1.1.0）也经同一条路说出。她躺着时不先开口：这要等状态接口返回坐、躺之后才能做到。

### 2. 契约 1.3.0 的"舞台"一节

- **动作词表与地点。**
  - 词表取自 MOSAIC `LiveSceneCommands`：`ChatMovements`、`ChatPlace` 用的去往词、邀请词与"说话人自己要去"的说法、`StandUpWords`、`ChatDanceKeywords`、`ChatGestures`、否定词；
  - 地点取自 `configs/scenes/home-v1.json`：10 个地点及其别名，例如沙发（客厅）、床（卧室、睡觉、躺）、钢琴（弹琴）。
- **判定向量。**
  - 由 MOSAIC 的实现生成（句子 → 动作），AIJADE 的实现必须在全部向量上一致，与 1.0.0 的主动开口向量做法相同；
  - 生成时不改 MOSAIC 仓库：在仓库外编译它的源文件副本，或请 MOSAIC 一侧生成后交来。
- **两条说明。** 取 `companion.py` 系统提示中 `app_action` 与 `where_you_are` 两句的意思，写成 AIJADE 的说明模板。

### 3. 交给 MOSAIC 的事（写成交接，经你同意后发送）

1. 状态接口返回"她在哪"：与交给它语言模型的同一句，以及坐着、躺着或站着。
2. 由外部驱动时关掉 `ProactiveSpeech` 与 `ModelActions`。这两项已有配置，不需要改代码。小脑的空闲动作可以保留。
3. 词表或地点变了时告知 AIJADE 一侧，与 1.2.0 的约定相同。

### 4. 在哪运行

- **服务端转发（建议）。**
  - AIJADE 服务端加一个接口，只把指令转给本机的工作台（目标只能是 `127.0.0.1` 或 `localhost`）；Web 与桌面应用都能用。
  - 这是新的服务端接口。ADR-002 在 1.1.0 时写过"不新增服务端接口"，所以要在 ADR-002 再补一节。
- **只做桌面应用。** 不改服务端，但 Web 端用不了。
- **同一台机器。** 两种做法都要求工作台与 AIJADE 在同一台机器上。不要把工作台的端口开到 Tailscale：它没有认证。

### 5. 工作量与验证

- **AIJADE 侧约 2 人日。**
  - 内容：契约与向量、判定实现、指令拼装、转发接口、设置开关（默认关闭）；
  - 测试：用测试替身代替工作台，检查发出的指令行；判定须在全部向量上与 MOSAIC 一致。
- **联机检查。** 要在 MOSAIC 里启动工作台和家（Godot 窗口），属于 MOSAIC 一侧的运行，何时做由你决定。

## 五、不影响论文的边界（同 ADR-002）

- 不改 `src/Aijade.Integrations/Renderer` 与渲染器契约。
- 12 月第 4 章外部渲染器运行期间不开舞台模式：用的是同一个 Godot 客户端，避免两种用途混在一起。
- 记忆召回仍经未改动的 `MemoryContext.cs`。舞台只在生成前加说明、生成后发指令，不改召回路径，也不新增学习观察者。
- MOSAIC 的走路可由"苍蝇脑"转向，即它的连接组控制器。这是 MOSAIC 产品的行为：AIJADE 对它不作任何主张，它也不进入学位论文。
- 不下载、不登录任何账号，除非你另行同意。
- 不进入研究，也不算研究进度。

## 六、建议

分两步做 A：
1. **先做契约 1.3.0 与判定实现。** 只改 AIJADE 的非研究线，不需要 MOSAIC 运行。同时（经你同意）发交接，请 MOSAIC 在状态接口返回"她在哪"。
2. **再做转发接口与界面开关。** 等你选定宿主（服务端转发，或只做桌面应用）后再做。

B 是现状，C 不做，D 没有融合价值，E 等两套记忆的问题有了答案再考虑。
