## 三、目标形态：三种做法

| 做法 | 做什么 | 好处 | 代价与风险 |
|---|---|---|---|
| **A. AIJADE 作大脑，MOSAIC 作身体** | AIJADE 提供一个对话接口：用契约的人设与 AIJADE 的记忆回复，MOSAIC 每轮附带的动作、地点、日程说明原样透传。MOSAIC 的 `companion_session.py` 把 `CompanionUrl` 指向它，此模式下停用自己的召回。身体、家、语音口型、作息仍在 MOSAIC | 一个艾娅德：一份记忆、一个人设，AIJADE 的渠道与工具都能用上她的家与身体 | 新增运行时耦合与接口（要另立 ADR-003）；两套记忆要选一套；AIJADE 服务端要与 MOSAIC 同机或带认证跨机；未在 Windows 上跑过 AIJADE 服务端 |

## 四、做 A 之前要定的事

1. **两套记忆。** 选一种：
   - **(a) 以 AIJADE 为准**：此模式下 MOSAIC 不召回，对话只存进 AIJADE 的记忆库；MOSAIC 的"过日子"事件经 AIJADE 已有的事件接口写进记忆（不改 `MemoryContext.cs` 与 `MemoryLibrary.cs`，它们是第 6 章 P3-E 冻结的文件）。
   - **(b) 各管各的**：对话记忆在 AIJADE，身体与作息的记忆留在 MOSAIC，每轮由 MOSAIC 把要紧的几条作为说明透传。
   - 建议 (a)：一个伴侣只有一份对话记忆，删除、导出、遗忘也只在一处。
2. **运行在哪里。**
   - MOSAIC 的日常运行在 Windows（RTX 5080 主机）。舞台转发要求 AIJADE 服务端与工作台同机（工作台没有认证，只走本机回环）。
   - 所以 A 的 AIJADE 服务端要么也在 Windows 上（连同 PostgreSQL；未在 Windows 上跑过，要先试），要么在 Mac 上，再给对话接口加令牌认证、经 Tailscale 访问；后一种舞台转发仍要另想办法。
   - 建议先在 Windows 上试 AIJADE 服务端，与舞台转发的联机检查一起做。
3. **身份。** 负责人在 AIJADE 里是哪一个用户；渠道消息（QQ、微信）是否也进同一个用户的记忆。
4. **渠道归谁。** QQ 与微信继续由 MOSAIC 的桥接收发（它们装在 Windows 上，已获批准）；Discord、Telegram、X、Satori 与 B 站直播间由 AIJADE。A 之下，两边的渠道都用同一个大脑。
5. **主动开口由谁发起。** MOSAIC 有作息与提醒，AIJADE 有"她先开口"。A 之下建议仍由 MOSAIC 决定何时开口（它知道她在做什么），说什么由 AIJADE 生成，规则仍按契约。
6. **声音。** MOSAIC 的固定声线与口型对齐已在 Windows 验证。A 之下她在家里说话用 MOSAIC 的声音；AIJADE 的网页与 Android 端仍用自己的合成。
7. **底座与工具。** MOSAIC 的 superagent 能开工单、调执行器；AIJADE 有 MCP 与工具中枢。可以让 superagent 把 AIJADE 的 MCP 工具当作执行器，但这一步放在 A 之后，另行决定。

## 六、不影响论文的边界（同 ADR-002，并补上共用机器）

- **只改非研究线**：不触及 `configs/project-scope.json` 中的研究对象，包括外部渲染器链路 `src/Aijade.Integrations/Renderer`，以及 P3-E 冻结的 `MemoryContext.cs` 与 `MemoryLibrary.cs`（内容哈希记在项目范围配置中）。
- **不进入研究**：整合后的伴侣、它的对话与真实使用不作为研究的输入、样本、奖励或判定条件。负责人与她的对话属于真实用户数据，不进入研究（ADR-001 非研究线规则 6）。
- **研究运行时关掉整合**：P1-C 与第 7 章的会话中舞台转发关闭（P1-C 方案已写明）；第 6 章 P3-E 的运行不打开舞台与对话接口；P3-E 的隔离存储不是整合所用的产品存储。
