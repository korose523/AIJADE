# 陪伴功能、Web 与 QQ 配置

AIJADE 的角色、生活与地点时区、关系状态和媒体收藏按账号及角色保存。网页与 QQ 连接同一 AIJADE 服务；修改保存后，后续新回合读取新状态。研究装置与产品数据的边界见 [PROJECT-SCOPE](PROJECT-SCOPE.md)。

## 开始使用与跨端同步

1. 登录网页，在“角色”页创建或修改角色，点击“与此角色聊天”。
2. 在“陪伴生活”填写住处、外貌、兴趣、朋友、发型、城市、时区和天气偏好，分别保存。城市可离线手填，也可查询后选择候选；开启天气需要完整经纬度。时区使用 IANA 名称，如 `Asia/Seoul`；角色资料留空时使用服务端返回的共享时区。
3. 若 QQ 机器人和网页使用不同账号，在网页“网页与 QQ 同步”生成绑定码，在机器人负责人 QQ 私聊发送 `/bind 绑定码`。绑定码十分钟内有效，只能使用一次，不进入普通聊天或记忆记录。
4. 两端随后共用所选角色、生活资料、关系与收藏。正在生成的回合沿用开始时的角色，下一回合采用新选择。网页每三秒检查共享状态，有未保存修改时保留草稿并提示刷新。
5. 网页“解除 QQ 绑定”会撤销授权，机器人恢复使用自己的账号资料。跨账号绑定不合并原有聊天历史、提醒或私人记忆。一个 QQ 号只接入一个回答端，避免 AIJADE 与其他机器人重复回复。

不同角色的关系和收藏相互隔离。公共角色的人设可以共用，私人关系与收藏仍归各自账号。并发保存使用版本检查，冲突时读取新版本再保存；旧设备数据只复制一次，不覆盖已有共享资料，也不恢复已删除的收藏。

## 功能与命令

| 功能 | 操作及生效范围 |
|---|---|
| 自然节奏与主动联系 | 分别启用；Web 主动检查依赖页面打开，机器人宿主可独立运行。主动联系遵守安静时段、暂停、告别、冷却和未回复限制；机器人重启后先等对方联系。角色未指定时区时，旧机器人配置优先于主机时区 |
| 虚拟生活与关系 | `/life`、`/relationship`；虚拟日程、兴趣、朋友、发型和穿搭随角色时间变化。关系按实际交互更新，同一消息不重复累计，离线不扣好感；这些规则不代表心理测量或真实感情 |
| 表情与季节衣柜 | 网页上传；QQ 图片加 `/sticker joy 名称` 或 `/outfit winter 名称及描述`。支持中文指令“收藏表情”“添加衣服”。每角色最多 32 项，单项最多 2 MiB；网页删除后，后续 QQ 发送不再选取该项 |
| 照片 | `/photo selfie`、`/photo snapshot`、`/photo landscape`；需要启用绘图并配置图像路由。生活快照提供外貌、时间、地点、活动、天气与服装描述；参考图保存于收藏，生成使用其描述，人物与服装一致性取决于图像服务 |
| 语音与歌声 | `/sing 歌名` 优先匹配已有录音，未匹配时可调用已配置的本地歌声服务。QQ 使用真实 image/record 段；不支持音频的渠道会说明限制。语音与歌声服务、音色和授权样本均可稍后配置 |

天气来自 Open-Meteo 的模型估算，不读取设备定位；缓存约二十分钟，过期或失败时明确不可用。角色生活属于虚拟设定。图像、语音和歌声只有取得实际媒体后才交付。

## 机器人设置

继续使用既有服务器、机器人登录令牌与 OneBot 负责人、令牌和签名密钥配置。下面仅列可选的非秘密字段；私有状态目录放在仓库外。地点、角色和收藏迁移或绑定后，以共享服务端资料为准。

```json
{
  "Bridge": {
    "SpeakFirst": true,
    "Drawing": true,
    "StateFile": "/your/private/aijade-bots-state.json"
  },
  "Companion": {
    "Enabled": true,
    "NaturalPacing": true,
    "Home": "窗边的小屋",
    "City": "",
    "Latitude": null,
    "Longitude": null,
    "TimeZone": "Asia/Seoul",
    "Weather": false
  },
  "OneBot": { "Voice": true, "SpeakReplies": true, "TtsVoice": "alloy" }
}
```

`OneBot:Voice` 控制入站转写，`OneBot:SpeakReplies` 控制出站语音。QQ 收藏图片只读取允许的 QQ CDN HTTPS 地址，下载不携带 NapCat 令牌。其他平台配置见 `src/Aijade.Bots/Program.cs`，共享人设与主动开口规则见 [COMPANION-CONTRACT](COMPANION-CONTRACT.md)。

## 随时配置本地音色服务

管理员在“陪伴生活 → 本地语音与歌声”（`/companion/services`）分别设置合成、识别、对齐和歌声的服务地址、音色、模型目录、授权样本目录及来源说明。可先保存为停用状态，以后再启用；保存某项只切换该项的本地路由，保留其他网关配置及密钥。后续请求读取新设置。

保存配置不启动训练，也不核验模型文件；模型和样本目录是记录字段。连接检查仅请求健康接口，最多等待五秒；修改地址后清除旧检查状态。专属音色训练与真实听感仍需要授权数据、实际模型和独立验收。

可选歌声适配协议如下；已有语音 `/tts`、`/transcribe` 和 `/align` 协议保持各自约定。

```text
POST {singing.upstream}/sing
Content-Type: application/json
{"song":"歌名","voice":"音色标识"}

200: WAV 字节，至多 8 MiB
404 或 422: 未知曲目
```

`voice` 留空时省略该字段。健康接口默认为 `GET {upstream}/health`，路径可配置。登录用户经 `/api/v1/openai/v1/audio/singing` 调用适配器；错误音频或服务故障会明确失败。该协议不表示已经部署歌声模型，也不表示 MOSAIC 已提供对应服务。

## 验证记录与边界

[工程回执](../experiments/engineering/2026-11-10-github-validation/receipt.json)保留修复前失败和最终结果：定向测试 78 通过、0 失败、5 个真实 Minecraft 环境项跳过；浏览器 8 通过、0 失败、0 跳过；预检监测器故障测试 8 通过。源码测试覆盖账号与角色隔离、绑定生命周期、保存冲突、关系幂等、时区优先级、收藏增删及完整聊天。

浏览器检查使用真实 AIJADE 服务、PostgreSQL、Chromium 和签名 OneBot 入站链路；模型、QQ 出站及图片源为受控替身，媒体夹具包含短 WAV 与小图片。记录证明所测流程的工程行为，真实 QQ/NapCat 到达、艺术效果、专属音色训练和长期陪伴效用仍需各自验收。产品测试不替代论文主实验。
