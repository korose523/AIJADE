# 12 个视频的参考核对与 AIJADE 独立实现

核对日期：2026-11-16。遵循作者要求，所有产品功能在 AIJADE 内独立实现；参考仓库用于理解设计、接口与失效案例，不复制源码，不安装整套第三方插件，不导入其角色图片、音色或模型资产。产品继续采用现有 .NET 共享运行库、服务端状态、渠道适配和交付记录。

## 来源覆盖与证据边界

本轮取得 12 个视频的介绍，音轨合计 6,471 秒（107 分 51 秒），经 65 次有界评论读取取得 330 条去重评论记录，并为每个视频在约 10%、50%、90% 处抽取并检查 3 帧，共 36 帧。音轨使用本地 faster-whisper tiny / CPU int8 逐段转写；这是有错误的机器转写，不是作者校订字幕，也不是连续逐帧观看。官方字幕读取需要 SESSDATA，本轮未取得登录权限；不能因此断言视频没有字幕。评论翻页遇到空页或重复记录即停止，不声称覆盖全部公开评论。

9 个可访问的直接参考仓库已核对固定提交的说明和许可证，其中 8 个采用标准开源许可，1 个采用自定义插件许可。部分仓库另读了设计文档、实现或测试。机器可读的来源、版本、读取深度、哈希和排除依据见 [references.json](evidence/video-references-20261116/references.json)。原视频音轨、抽帧、完整转写、评论正文及第三方源码阅读副本仅留在本机 AIJADE 的 `.research/` 目录；不随项目代码公开。

## 本轮已经独立实现的逻辑

`ChannelScope` 统一定义通用机器人桥接层的聊天、记忆和后备笔记本范围，`CompanionBridge` 与 `CompanionConfiguration` 使用同一处定义。状态隔离由代码决定，不依赖提示词让模型保密。

| 状态 | 私聊兼容方式 | 群聊的新范围 |
|---|---|---|
| 聊天历史、锁、限流 | 保留原平台/会话 key，旧聊天映射可继续读取 | 平台与群 ID 的 JSON 元组摘要；与同数字 ID 的私聊分开 |
| 长期记忆写入与召回 | 保留 `bot:平台:发言人` | 平台、群 ID、发言人共同决定；不回退到旧的混合范围 |
| 后备关系与收藏 | 保留原平台/发言人/角色 key | 平台、群 ID、发言人、角色共同决定；重启后仍隔离 |
| 已绑定 QQ 私聊与网页 | 继续使用既有服务端授权、角色选择、修订号和同步接口 | 群聊不借用私聊绑定授权 |

JSON 元组再取 SHA-256 可避免简单用冒号拼接产生标识歧义。群里的公开聊天历史由该群共享；长期记忆仍按群内发言人细分。隔离不表示同群成员永远看不到已经在该群公开发送的内容。

旧实现按平台/发言人保存长期记忆，同一人在群聊和私聊中使用相同范围；聊天 key 也没有区分私聊与群聊类别。因此同号群可能复用私聊历史，群内还可能召回私聊内容。旧数据没有足够来源信息，不能自动证明其适合公开。本轮保留旧文件和服务端记录，群聊从新的范围开始；没有自动搬运、删除或重新标注旧记忆。需要恢复的旧群资料应先补可核对的来源及授权，再单独设计迁移。

回复频率也改为在会话锁内用当前时钟复核。首轮模型调用较慢时，多个群事件可能同时通过锁外检查；排队后再次检查，避免随后连续生成多条回复。其他群使用各自的锁，私聊继续依照原流程处理。

本轮验证的是通用 `CompanionBridge`，测试经真实服务端与 PostgreSQL，模型使用本地固定替身。**QQ 原生 OneBot 适配器目前仍只接收已授权主人的私聊**；本轮未启用 QQ 多群或微信，也未向真实 QQ 发送测试消息。网页/QQ 授权同步由既有集成测试继续核对，不能将桥接层的合成群测试写成真实多群验收。

## 独立实现的后续顺序与验收条件

以下是待实现的产品能力，不是本轮完成项。每项复用现有运行库和服务端状态，不增加另一套插件宿主、人格数据库或无限模型循环。

| 顺序 | AIJADE 内的设计落点 | 完成时必须验证 |
|---|---|---|
| 1：分段输入与生活连续性 | 在既有入站队列上增加有界合并窗口；消息 ID、来源和原始文本保留；显式命令及媒体导入单独处理。生活候选来自已存状态与日程，再经过原主动门控 | 连发半句话只生成一次合并回复；窗口上限、关闭选项、取消和重启行为明确；没有将主动消息伪装成用户输入；冷却、安静时间、无人回复退避继续生效 |
| 2：一起看与来源完整性 | 将视频 ID/地址、播放位置、字幕区间、帧时间、内容摘要与会话绑定；动态观察进入当前轮，沿用提示预算与交付记录 | 换片、跳转、暂停时作废过期片段；字幕必须属于同一视频；只有抽帧时明确覆盖范围；有输出并取得真实发送结果后才记交付状态 |
| 3：按键语音与移动感知 | 现有 ASR/TTS 路由上增加当前会话的输入授权及可取消播放队列；本地模型/服务地址继续可配置 | 摄像头/麦克风有明确启动动作，退出前台停止；旧语音不会跨角色/会话播放；用户要求只打字时不强制语音；无服务时明确不可用 |
| 4：短期情绪与日记 | 在现有生活模块和笔记本中独立保存短期情绪、触发依据、时间与衰减；稳定人设和关系仍分别管理 | 状态可检查、关闭与重置；相同消息只更新一次；不因未回复惩罚关系；不把模拟情绪当生理或意识测量；日记有来源和版本，不倒灌为用户原话 |
| 5：虚拟房间与可编辑角色 | 房间/衣柜/动作是已有角色状态的显示层；通过现有 `PerformanceIntent` 和渲染适配输出；使用自有或获授权资产清单 | 修改角色、时间地点及服装后各端一致；资源许可逐项可核对；图层缺失或被遮挡部件明确报出；渲染失败不改变聊天及研究判定 |
| 6：备份与迁移演练 | 对服务端同步状态及本地后备笔记本做明确版本的导出、校验和隔离恢复；不以恢复脚本自动覆盖现用数据 | 原始记录、收藏、绑定和关系计数可对账；错误/截断备份拒绝导入；恢复到隔离目录后逐项核对；撤销授权不会因旧备份而复活 |

## 验证与研究版本

新增 `ChannelAudienceTests` 的 5 项回归覆盖私群记忆、同号历史、群内人物/群间后备状态和并发限流。同一组新增测试在修改前的生产实现上全部失败，在修复后的最终全套回归中全部通过。Mac 默认代码测试为 689 通过、29 跳过、0 失败，共 718 项；GitHub Linux CI 为 687 通过、31 跳过、0 失败，共 718 项。两端的 38 项浏览器可选测试均未启用，记为跳过。

20 项 CI 档案与控制检查均已通过。Mac 自带 Python 3.9 在 5 项检查中不能解析已有七位小数时间戳或缺少 `hashlib.file_digest`；原失败日志保留，使用项目现有 Python 3.12 复核通过，没有修改时间戳、原始数据或历史验证器。历史快照守卫还实际拒绝了错误源码提交和被改动的档案副本。精确计数、代码版本和回执哈希见 [validation.json](evidence/video-references-20261116/validation.json)。

本轮是产品工程更新，不增加论文样本、模型判断或留出实验。历史研究包及其 331 个冻结源码的记录不改写。CI 使用固定提交 `f90f04110f46fb17a2a43a777ed5d4e68a361902` 验证原始历史清单，同时逐文件核对当前仓库仍保留原包；当前产品代码另跑回归。该历史核对输出明确 `currentProductResearchQualified=false`，不把新产品自动纳入旧研究结论或硬件资格。
