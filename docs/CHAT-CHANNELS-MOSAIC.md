# 聊天平台：AIJADE 与 MOSAIC 的对照与方案（非研究线）

2026-10-28，作者要求在与 MOSAIC 非研究线融合的过程中，先写清两边聊天平台对接的现状与可选方案，再决定是否实现。本文只是对照与方案，没有改代码。范围与边界见 [ADR-002](decisions/ADR-002.md) 与 [COMPANION-CONTRACT](COMPANION-CONTRACT.md)；MOSAIC 一侧只读，内容取自它 2026-10-28 的文档 `docs/COMPANION-QQ-2026-10-28.md` 与 `docs/COMPANION-ASTRBOT-2026-10-28.md`。

## 一、现状

| | AIJADE | MOSAIC |
|---|---|---|
| **平台** | Discord（gateway）、Telegram（长轮询）、Satori 协议（Koishi 等的跨平台 WebSocket）、X、哔哩哔哩直播；连接器在 `src/Aijade.Bots` 与 `src/Aijade.Integrations` | QQ 私聊：经 NapCat 的 OneBot 11 HTTP 接口（`tools/companion_qq.py`，r383） |
| **谁能和她说话** | 多用户：私聊总是回答；群里被提到、被回复或叫到名字（艾娅德、Aijade）时回答；同一会话 3 秒内最多一条 | 只回负责人本人（`--owner-qq`）的私聊；群消息、陌生人只计数，不读内容 |
| **对话与记忆** | 经 `CompanionBridge` 进入服务端聊天，每个平台会话一个聊天；记忆按人分开（`bot:{平台}:{作者}`） | 与实时场景同一个数据库、同一个用户：QQ 上说的话，回到屏幕前她也记得 |
| **安全** | 每个连接器各自的平台令牌；工具默认关闭（公开群里的人不能让她操作负责人的设备） | 推送必须带签名（HMAC-SHA1），令牌与密钥从文件读；只监听 127.0.0.1，NapCat 地址只能是本机或 Tailscale 网络 |
| **语音与图片** | 文字；可选画图（需要服务端的图片路由） | 语音消息经 NapCat 取 WAV，交本机语音识别；图片回一句"我现在只看得懂文字和语音哦。" |
| **没有身体的渠道** | 系统提示中没有关于"这里没有身体"的说明；是否会答应做动作，没有测过 | 测过三步：每轮说明"这是手机上的 QQ 文字聊天，这里没有身体"；动作请求另加说明；回复里没有推迟的说法时补一句"等你回到屏幕前，我再做给你看。"。最后两遍实测 8 次动作请求全部推迟 |
| **出错时** | 这一轮失败，不回 | 回"抱歉，我刚才走神了，能再说一遍吗？" |
| **提醒与先开口** | 先开口只在 Web 聊天（契约 1.1.0，默认关闭）；渠道上没有 | 到点的提醒可发到 QQ；实时场景与 QQ 同时轮询时，先认领者发送，只发一次 |
| **日志** | 各连接器的运行日志 | 只记字数和用时，不记说了什么 |

## 二、两边的差别与能共用的部分

- **协议不是障碍。** OneBot 11 是公开的机器人协议，不是 NapCat 独有的。AIJADE 可以写一个 OneBot 11 连接器，不用 NapCat 的任何代码。
- **NapCat 本身有限制**，与 MOSAIC 文档所写相同：
  - 许可为《Limited Redistribution License》，不许商用，未经主作者许可不得使用、修改或基于其代码开发；
  - 它让官方 QQ 客户端以非官方方式工作，账号有被限制或冻结的风险；
  - 合规的替代是 QQ 开放平台的官方机器人，接口不同，两边都没有做。
- **同一个 QQ 号只能接一边。** 两边的对接都是 NapCat 推送消息的地址。同一个 QQ 号由两边同时回答，会回两遍，所以一个号只能交给一边。
- **记忆模型不同。** AIJADE 是多用户、按人分开的服务端记忆；MOSAIC 是负责人一人、与屏幕前共用一份记忆。把 MOSAIC 的 QQ 对接改走 AIJADE，就是换一套记忆，属于"AIJADE 作对话大脑"那条路，不在本文范围内。
- **能直接共用的是行为规则，不是代码。** MOSAIC 在 QQ 上测出来的几条，与平台无关，AIJADE 的文字渠道同样适用，可以写进伴侣契约：
  - 没有身体的渠道不答应做动作；
  - 出错时回一句；
  - 图片与语音的回复口径。

## 三、可选方案

| 方案 | 做什么 | 改动与风险 | 不做的后果 |
|---|---|---|---|
| **A. 共享渠道规则（建议先做）** | 契约升为 1.2.0，加入"文字渠道"一节：没有身体时的说明与补句、出错时的回复、图片的回复。AIJADE 的 `CompanionBridge` 采用；测试用 MOSAIC 的同一批句子 | 只改非研究线的 `CompanionBridge` 与契约；不改 `MemoryContext.cs`（P3-E 冻结路径）；行为只在聊天平台上变化；约 1 人日 | AIJADE 的文字渠道上，模型可能答应做动作 |
| **B. AIJADE 加 OneBot 11 连接器** | 新的 `IChannelConnector`：签名校验、只监听本机、可设只回指定号码；经 `CompanionBridge` 进入多用户聊天 | 新文件，不改现有连接器与记忆路径；用测试替身验证，不需要下载 NapCat；实际使用要装 NapCat（需你同意下载）、要一个 QQ 号扫码；同一个号与 MOSAIC 二选一；约 1–2 人日 | AIJADE 上 QQ 只能经 Satori（Koishi 等）间接接入 |
| **C. 渠道上也能先开口** | 把契约 1.1.0 的先开口规则用到私聊渠道；与 MOSAIC 的提醒一样，先认领再发送，只发一次 | 渠道连接器需要能主动发消息（Telegram、Discord 可以）；约 1 人日 | 先开口只在 Web 聊天 |
| **D. 暂不做** | 保持现状：负责人的 QQ 交给 MOSAIC，AIJADE 保留现有渠道 | 无 | — |

**建议**：先做 A。它把 MOSAIC 已测过的规则共享过来，只改 AIJADE 的非研究线，风险最小。B 只在你希望 AIJADE 的多用户伴侣也上 QQ 时再做；C 可在 A 之后进行。
