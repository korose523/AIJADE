# KIMODO → VRM Offline Gesture Clips

This folder serves **real, offline-generated body-motion clips** for AIJADE's VRM
avatars. At runtime, `packages/stage-ui-three/src/libs/kimodo-gestures.ts`
fetches `manifest.json` from here (and `/hy-motion/`) and builds VRM
animations — no Python / no GPU is needed in the browser.

## How the clips are produced

Motion is generated by **NVIDIA KIMODO** and retargeted onto VRM human bones:

```
KIMODO text-to-motion  ──▶  motion.npz (SOMA 30/77-joint skeleton)
        │
        ▼
retarget_soma_to_vrm.py  ──▶  <name>.json  (VRMAnimation-compatible clip)
        │
        ▼
apps/stage-web/public/kimodo/  (served statically)
```

The retargeter uses the **position method** (per-bone direction vectors →
unit quaternions), which is skeleton-agnostic and axis/scale robust. An optional
**hips translation track** is emitted for locomotion gestures (dance) so the
avatar actually displaces.

## Model choice: SOMA (open) over SMPL-X (gated)

| Model | License | Status |
|-------|---------|--------|
| `nvidia/Kimodo-SOMA-RP-v1.1` | **NVIDIA Open Model** | ✅ used by default — no gate |
| `nvidia/Kimodo-SMPLX-RP-v1` | NVIDIA R&D Model | ⛔ gated — needs license request |

We default to the open **SOMA-RP-v1.1** model so the pipeline runs without
applying for restricted access. The SMPL-X variant is available if you obtain
the R&D license (see `retarget_soma_to_vrm.py --skeleton smplx22`).

## Regenerating the clips (needs a CUDA GPU)

```bash
# 1) Create the environment (Windows example)
uv venv -p 3.11 H:/kimodo_env
uv pip install --python H:/kimodo_env/Scripts/python.exe torch torchvision --torch-backend cu128
SKIP_MOTION_CORRECTION_IN_SETUP=1 \
  uv pip install --python H:/kimodo_env/Scripts/python.exe -e H:/kimodo_src

# 2) KIMODO's text encoder is LLM2Vec on meta-llama/Meta-Llama-3-8B-Instruct,
#    which is gated. The open LLM2Vec weights live in McGill-NLP repos; snapshot
#    them locally and point KIMODO at them so it never fetches the gated base:
uv pip install --python H:/kimodo_env/Scripts/python.exe huggingface_hub
H:/kimodo_env/Scripts/python.exe - <<'PY'
from huggingface_hub import snapshot_download
for r in ["McGill-NLP/LLM2Vec-Meta-Llama-3-8B-Instruct-mntp",
          "McGill-NLP/LLM2Vec-Meta-Llama-3-8B-Instruct-mntp-supervised"]:
    snapshot_download(repo_id=r, repo_type="model", local_dir="H:/text_encoders/" + r)
PY
export TEXT_ENCODERS_DIR=H:/text_encoders

# 3) Generate + retarget every gesture (downloads the SOMA model on first run)
cd packages/stage-ui-three/src/libs/kimodo
H:/kimodo_env/Scripts/python.exe build_clips.py --generate
```

`build_clips.py` writes `<name>.json` + `manifest.json` into
`apps/stage-web/public/kimodo/`. You can also retarget a single clip:

```bash
H:/kimodo_env/Scripts/python.exe retarget_soma_to_vrm.py motion.npz \
    --name wave --out wave.json --hips
```

## Clip JSON schema

```jsonc
{
  "name": "wave",
  "fps": 30,
  "duration": 3.0,
  "restHipsPosition": [0, 0.8, 0],
  "bones": {
    "leftUpperArm": { "times": [0, 0.033, ...], "rotation": [[x,y,z,w], ...] }
  },
  "translation": { "times": [...], "position": [[x,y,z], ...] }  // optional hips
}
```

Consumed by `buildVRMAnimation()` in `kimodo-gestures.ts`.

## Graceful degradation

If this folder is empty (no clips generated yet), `loadOfflineGestureClips`
returns `[]` and gestures fall back to **emote pulses** (facial expressions) —
the avatar still reacts, just without body motion.

## Generating MMD (`.vmd`) actions

AIJADE's AI free-form motion is **double-emitted**: every clip becomes both a VRM
JSON (for AIJADE's avatar) **and a `.vmd`** (for MikuMikuDance / MMD). One text
prompt → two formats.

```
KIMODO / HY-Motion text-to-motion
        │
        ├─ retarget_soma_to_vrm.py | retarget_smplh_to_vrm.py ─▶ <name>.json  (VRM)
        │
        └─ retarget_to_vmd.py (motion_common.build_vmd)      ─▶ <name>.vmd   (MMD)
```

`retarget_to_vmd.py` works for both skeletons (`--skeleton soma30 | smplh22`).
It uses **pypmxvmd** to write a valid VMD with Shift-JIS Japanese bone names
(センター / 上半身 / 左腕 / 左ひじ / …). Each MMD bone's **local** rotation is
computed relative to its nearest mapped ancestor, preserving the hierarchy so
playback is correct. The root (センター) carries the hip translation; MMD faces
−Z, so Z is negated by default (`--handedness mmd`).

```bash
# from packages/stage-ui-three/src/libs/kimodo
H:/motion_env/Scripts/python.exe retarget_to_vmd.py motion.npz \
    --name dance --out dance.vmd --skeleton soma30 --handedness mmd

# HY-Motion (SMPL-H 22) -> VMD
H:/motion_env/Scripts/python.exe retarget_to_vmd.py motion.npz \
    --name wave --out wave.vmd --skeleton smplh22
```

`build_clips.py` emits both `<name>.json` and `<name>.vmd` automatically and
writes a `manifest.json` declaring `"formats": ["vrm", "vmd"]`.

## HY-Motion (SMPL-H) as an alternative source

Tencent **HY-Motion 1.0** (`Tencent-Hunyuan/HY-Motion-1.0`) is a billion-parameter
DiT flow-matching text-to-motion model. Its output is **SMPL-H 22-joint** motion
(6D rotations + translation, fps 30) — not VMD/VRM. We retarget it through the
same pipeline:

- `retarget_smplh_to_vrm.py` → VRM JSON
- `retarget_to_vmd.py --skeleton smplh22` → VMD
- `motion_common.smplh_fk_from_rot6d()` converts HY-Motion's `rot6d`+`transl`
  into world joint positions before retargeting.

Run it with:

```bash
cd packages/stage-ui-three/src/libs/kimodo
H:/hy_motion_env/Scripts/python.exe build_clips.py --generate --source hy-motion
```

## Expressiveness (emotions + idle) — TS runtime

`packages/stage-ui-three/src/libs/emotion/avatar-expression.ts` adds three
reusable helpers distilled from the companion/emotion projects we reviewed:

- **`normalizeEmotionLabel`** (Akane `EmotionMapper`) — arbitrary LLM emotion
  label → a valid VRM preset via an alias table + `neutral` fallback.
- **`padToPreset`** (astrbot `expression.py`) — a continuous PAD
  (Pleasure-Arousal-Dominance) vector → dominant VRM preset + intensity, so the
  face reacts smoothly instead of snapping between presets. Exposed to the
  performance layer as `setEmotionPAD(pad)`.
- **`IdleSpontaneousController`** (leuke `silence_loop`) — a silence clock with a
  refractory cooldown: after the user is quiet for a few seconds, the avatar
  occasionally fires a micro-gesture (think / nod / shrug) instead of freezing.

Wired into `useAvatarAnimation()` in `composables/vrm/use-avatar-animation.ts`.
